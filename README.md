# User Stories — Формулирование требований от лица пользователя

## О проекте
Учебный проект Школы 21 (индивидуально).  
Разработал комплекс user stories для документирования функциональных требований и создания бэклога продукта.

## Моя роль
- Выявил потребности пользователей через интервью и анализ
- Сформулировал user stories в формате "Как... Хочу... Чтобы..."
- Определил критерии приемки (acceptance criteria)
- Приоритизировал истории по методу MoSCoW

## Выполненные задачи

### Задание 1: Идентификация пользовательских ролей
- Определил основные пользовательские персоны (personas)
- Описал характеристики, цели и боли каждой персоны
- Выявил сценарии использования для каждой роли

### Задание 2: Формулирование User Stories
- Создал user stories в стандартном формате
- Добавил критерии приемки (Given/When/Then)
- Обеспечил независимость и тестируемость историй

### Задание 3: Приоритизация (MoSCoW)
- Классифицировал истории: Must have, Should have, Could have, Won't have
- Обосновал приоритеты с точки зрения бизнес-ценности
- Сформировал продуктовый бэклог

### Задание 4: Декомпозиция и оценка
- Разбил крупные истории на более мелкие (epics → stories)
- Оценил сложность через story points
- Выявил зависимости между историями

## Результаты
- ✅ 20+ user stories с критериями приемки
- ✅ Продуктовый бэклог с приоритетами MoSCoW
- ✅ Персоны пользователей с детальным описанием
- ✅ Готовые артефакты для передачи в Agile-команду

## Инструменты
- Jira / Trello / YouTrack
- User Story Mapping
- MoSCoW prioritization
- BDD (Given/When/Then)
