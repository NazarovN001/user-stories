# User Stories — Пользовательские истории

## О проекте
Учебный проект Школы 21 (индивидуально).  
Изучил метод User Story (US) как способ быстрой и краткой фиксации потребностей пользователей в системе. Научился создавать пользовательские истории с критериями приёмки и тестовыми сценариями, а также проводить их согласование с участниками процесса разработки.

## Моя роль
- Определил потребности ключевых ролей в системе онлайн-записи для барбершопа
- Сформулировал пользовательские истории в формате "Как [роль] я хочу [действие], чтобы [ценность]"
- Разработал критерии приёмки (Acceptance Criteria) в формате Given/When/Then
- Составил тестовые сценарии для проверки реализованных US
- Провёл обсуждение и согласование US с участниками в ролях пользователя, заказчика и разработчика

## Выполненные задачи

### Задание 1: Описание пользовательских историй для менеджера (ex00)
- Определил не менее двух потребностей роли менеджера в системе
- Для каждой потребности написал US: идентификатор, заголовок, роль, ценность, требуемые действия
- Для одного US разработал критерии приёмки (предусловие, действие, результат)
- Для второго US разработал тестовый сценарий (предусловия, действия, ожидаемый результат)

### Задание 2: Описание пользовательских историй для клиента и мастера (ex01)
- Выбрал две роли, отличные от менеджера: клиент и мастер
- Определил для каждой роли не менее двух потребностей в системе
- Для каждой роли написал US с указанием идентификатора, заголовка, роли, ценности и действий
- Для каждой роли по одному US описал критерии приёмки
- Для каждой роли по второму US описал тестовый сценарий

### Задание 3: Согласование пользовательских историй (ex02)
- Провёл обсуждение разработанных US с участниками в ролях пользователя, заказчика и разработчика
- Проверил выполнение условий 3C: Card (компактность), Conversation (обсуждение), Confirmation (согласование)
- Проверил характеристики INVEST: независимость, обсуждаемость, ценность
- Составил протокол обсуждения с указанием участников, ролей, внесённых изменений и причин изменений

## Результаты
- 6+ пользовательских историй для трёх ролей (менеджер, клиент, мастер)
- Критерии приёмки для ключевых US в формате Given/When/Then
- Тестовые сценарии с предусловиями, действиями и ожидаемыми результатами
- Протокол согласования US с фиксацией изменений и их причин

## Инструменты
- Формат User Story: "Как [роль] я хочу [действие], чтобы [ценность]"
- Критерии приёмки (Acceptance Criteria) в формате Given/When/Then
- Тестовые сценарии (Test Scenarios)
- Принципы 3C: Card, Conversation, Confirmation
- Критерии INVEST: Independent, Negotiable, Valuable, Estimable, Small, Testable

## Структура проекта
- `src/ex00_barb_us_manager.docx` — пользовательские истории роли менеджера с критериями приёмки и тестовым сценарием
- `src/ex01_barb_us_client.docx` — пользовательские истории роли клиента
- `src/ex01_barb_us_master.docx` — пользовательские истории роли мастера
- `src/ex02_barb_us.docx` — протокол обсуждения и согласования пользовательских историй
